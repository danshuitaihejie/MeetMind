# MeetMind 识别质量

目标是定位错误第一次出现的环节，修正受影响的会议，并让同类错误在以后被发现或阻止。先读当前仓库的 `AGENTS.md`、处理流程和测试；一次案例的正确词不等于所有会议的全局替换规则。

## 追溯证据

1. 从用户给出的聊天会话、任务 ID 或文件名定位会议。只输出定位所需的少量片段；不把完整会议、凭据或大量 OCR 行写入日志。
2. 沿数据流比较首次快速转写、原速词级转写、校对候选与确认记录、最终转写、纪要和问答上下文。MeetMind 的常见位置是 `data/chat_sessions.json`、`data/jobs/<id>/transcript.original.txt`、`review/segments.original.json`、`review/segments.json`、`review/segments.corrected.json`、`transcript.txt` 和 `job.json`。先判定是 ASR、OCR、候选遗漏、回写还是问答引用出了问题。
3. 对视频争议词按词级时间戳抽取少量原画面，并检查发声前后数秒；界面中的命令、标题可能在说出词后才出现。先看实际帧，再运行本地 OCR。OCR 行可能被大量界面文字淹没，检查目标词是否在截断前存在，以及其形态是否带 `/`、`-`、空格或大小写变化。
4. 对两版 ASR 的专名冲突，优先形成待核对候选并提供原声与画面证据。OCR 或模型估值只是证据，不能替代人工确认；找不到证据时保留不确定性。

## 修复和验收

- 修复流程时，针对根因增加可观察的检测、证据采样或回写保护。不要把单个词的硬编码替换当作质量提升；对真实常见词之间的歧义，确认结果只作用于对应会议，避免污染全局纠错记忆。
- 纪要术语修正看似未生效时，先核对页面所选版本与最新版本，并分别统计纪要和词级转写中的精确写法及大小写、空格变体。纪要直接修正只新增版本；若转写仍保留旧变体，再生成可能重现旧写法。按本会议已确认的证据统一转写变体，保持句段与词级 token 对齐，并确认再次应用校对时不会把仅限本会议的修正升级为全局规则。
- 修复已有会议时保留原始 ASR 和修改前数据，核对句段文本、词级 token、时间戳、最终转写和问答输入一致；纪要若含错误事实，按产品流程重新生成或明确修正。保留历史聊天记录的时间顺序。
- 用真实失败样本复验关键证据，再加一个针对机制的回归测试和一个误伤反例。至少核查候选能被发现、稍后出现的画面能被取到、相关 OCR 行不会被截断、未经确认的冲突不会覆盖正确文本，以及局部纠错不会改写正常用词。候选数量上限需与提交接口容量匹配；批量填入不能悄悄确认需逐项核对的冲突。运行项目现有测试和静态检查；浏览器验收仅在交互行为需要核实时进行。
- 更换 ASR 或文本服务时，分别验证普通转写、词级时间戳结构、文本模型的 JSON 输出及用量字段。只有 `text` 的语音接口可处理会议，但不能声称支持词级校对；缺少 `words` 时间戳时应明确失败，不要用句段时间冒充词级证据。新服务的识别质量应以同一批真实会议样本比较，不能仅凭接口兼容断言更准确。
- 汇报错误起点、修复范围、实测证据与仍未覆盖的情形，区分“代码测试通过”和“真实会议重新处理通过”。

## 后续更新此 skill

出现新的真实误识别时，先完成上述归因和复验，再把**会改变下一次判断或操作**的通用经验合并进本文件；案例细节放在 `references/`。复查旧规则是否被新证据推翻，删掉失效或重复内容，运行 `skill-creator/scripts/quick_validate.py`。此 skill 不自行安排周期任务，也不扩大当前用户授权的数据修改范围。
